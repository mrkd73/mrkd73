# پرامپت نقش تیم — راهنمای استفاده

دو نسخه از یک پرامپت، برای کنترل هزینهٔ توکن بدون افت کیفیت.

| فایل | کِی استفاده شود | تقریب حجم |
| --- | --- | --- |
| `team-role-prompt-lite.md` | پیش‌فرض هر چت روزمره: باگ کوچک، تغییر UI، کار کمتر از ~۳ فایل | ~۱/۵ نسخهٔ کامل |
| `team-role-prompt.md` | کار "مهم": معماری، مدل داده، پول/امنیت، فیچر جدید، تصمیم محصولی | کامل |

## روش کار

نسخهٔ lite را به‌عنوان system/project instructions پیش‌فرض بگذار. اگر کار از مرز
`<escalate>` رد شد، خودش اعلام می‌کند که کار «مهم» است و نسخهٔ کامل لازم است —
آن‌وقت نسخهٔ کامل را بده تا فرایند دو فازی (اسپک، بعد پیاده‌سازی) اجرا شود.

دلیل این تقسیم: کل متن پرامپت در هر پیام وارد context می‌شود، چه استفاده شود چه
نشود. قانون داخلی («برای کار ساده عمیق پردازش نکن») هزینهٔ فکر را کم می‌کند ولی
هزینهٔ ورودی را نه. تنها راه واقعی کاهش توکن، لود نکردن متنی است که لازم نیست.

## تفاوت محتوایی

نسخهٔ lite این‌ها را ندارد: ساختار ۱۲بخشی، `gap_analysis`، فرایند دو فازی،
`synthesis_process`، قالب رسمی خروجی. در عوض `<escalate>` دارد که مانع می‌شود
کار مهم با ابزار ناکافی انجام شود.

قوانین سختی که در **هر دو** نسخه هستند (نباید از lite حذف شوند): اختیار
کارفرما، `build_or_not`، استانداردهای نام‌گذاری، چک‌لیست امنیتی وردپرس،
`definition_of_done`، قواعد متن رابط کاربری، زبان کامنت.
